# stroke_reproducibility_rebuilt (v3) — NEURI-D-26-00184

Reproducibility project for *First-Month Mortality after Stroke in a Cameroonian Registry: Outcome Ascertainment and Development of an Admission-Time Prediction Model* (revision of NEURI-D-26-00184, *Neuroscience Informatics*). It contains the exact code that produced every number, table and figure of the revised manuscript, the versioned outcome definition with its approval state, the reviewer-ticket register and an automated self-check that re-verifies every ticket after each run.

## Quick start (PyCharm, Windows)

1. **Open the project.** File → Open → select the inner folder `stroke_reproducibility_rebuilt` (the one that contains `run_all.py`), not the outer `…_v3` folder.
2. **Interpreter.** File → Settings → Project → Python Interpreter → Add → Virtualenv (Python 3.11 or newer). Then in the PyCharm Terminal (View → Tool Windows → Terminal, which opens inside the project folder):
   ```powershell
   python -m pip install -r requirements.lock
   ```
   If `python` opens the Microsoft Store, use `py` instead.
3. **Data.** See *Data repository* below. Minimum: `database_stroke_copy.xlsx` in `data/raw/`.
4. **Run** from the PyCharm Terminal:
   ```powershell
   python run_all.py --mode audit                              # ~2 min: integrity, duplicates, dates, dictionary, endpoint provenance
   python run_all.py --mode all --accept-provisional --clean    # ~45 min: full analysis, tables/figures, letter, 99 checks, ticket self-check
   ```
   Or make a Run Configuration: Run → Edit Configurations → + → Python; *Script path* = `run_all.py`; *Parameters* = `--mode all --accept-provisional --clean`; *Working directory* = the project folder. Add `STROKE_SYNTHETIC=1` under *Environment variables* for the synthetic demonstration (see below).
5. **Results.** `outputs/` (tables, figures, audit, analysis, reports, logs, manifests), `manuscript/tables`, `manuscript/figures`, `manuscript/main.pdf`, `docs/data_quality_report.md`, `docs/ticket_closure.md`.

`--accept-provisional` is required because `config/outcome_definition.yaml → approval_state` is `DICTIONARY_SUPPORTED_NOT_CUSTODIAN_VERIFIED`: the registry's dictionary defines the month-1 field but does not state its time origin explicitly. The runner refuses the reconstructed mode otherwise and never falls back silently. `--clean` deletes `outputs/` and `data/processed/` only; `data/raw/` is never touched.

**Workbook stored elsewhere.** Instead of `data/raw/`, set the variable before running — PowerShell: `$env:STROKE_DATA_PATH = "G:\secure\database_stroke_copy.xlsx"`; cmd: `set STROKE_DATA_PATH=G:\secure\database_stroke_copy.xlsx`; Linux/macOS: `export STROKE_DATA_PATH=/secure/database_stroke_copy.xlsx`; or add it to the Run Configuration's environment variables.

**LaTeX.** The manuscript PDF, the response letter and the 99-check verification need `pdflatex` and `bibtex` (MiKTeX on Windows, TeX Live elsewhere). Without them the run still completes and the log records that compilation was skipped; tables, figures and macros are generated regardless.

## Run it without patient data (synthetic demonstration, ~20 min)
```powershell
python scripts/make_synthetic_fixture.py                  # synthetic registry with the real headers and codings
$env:STROKE_SYNTHETIC = "1"                                # cmd: set STROKE_SYNTHETIC=1   Linux/macOS: export STROKE_SYNTHETIC=1
python -m pytest -q tests                                  # 29 tests
python run_all.py --mode all --accept-provisional --quick --clean
Remove-Item Env:STROKE_SYNTHETIC                           # cmd: set STROKE_SYNTHETIC=   Linux/macOS: unset STROKE_SYNTHETIC
```
Synthetic outputs are stamped `SYNTHETIC_DATA_RUN.txt`, the manuscript compiles to `main_SYNTHETIC_DEMO.pdf`, and the results are meaningless clinically. Binder (`binder/`), Docker (`Dockerfile`) and GitHub Actions (`.github/workflows/ci.yml`) run the same demonstration online; `notebooks/run_online.ipynb` does it step by step.

## Data repository (`data/`)

```
data/
├── raw/                      registry inputs, read-only, git-ignored, never copied into outputs or archives
│   ├── database_stroke_copy.xlsx        ← required (the analysed workbook; MD5 08541ef199c1656c184291f24b4cc3e3 is checked at start)
│   ├── stroke_data_dictionnary.xlsx     ← optional; either spelling (…dictionary/…dictionnary), xlsx or database_stroke_dict.csv
│   └── README.md
├── interim/                  reserved (empty); stage checkpoints go to processed/ckpt
├── processed/                row-level intermediates written by the run (cohort pickles, restricted annex); git-ignored; never distributed
└── synthetic_fixtures/       synthetic_registry.xlsx generated by scripts/make_synthetic_fixture.py (no patient data)
```

How the inputs are resolved, in order:

| Input | Resolution order | Check |
|---|---|---|
| Registry workbook | `STROKE_SYNTHETIC=1` → synthetic fixture; else `STROKE_DATA_PATH`; else `data/raw/database_stroke_copy.xlsx` | MD5 must equal `08541ef1…` (real runs) |
| Data dictionary | `STROKE_DICT_PATH`; else the first of `data/raw/stroke_data_dictionary.xlsx`, `data/raw/stroke_data_dictionnary.xlsx`, `data/raw/database_stroke_dict.csv`; else the shipped `dictionary/stroke_data_dictionary.xlsx` | MD5 compared with the two recorded versions (xlsx `be778aa0…`, CSV `e7c33acf…`, identical content); an unrecorded version is audited with a warning and its checksum is written to the manifest |

Both versions of the dictionary are accepted (the CSV is `;`-delimited, cp1252). Do **not** place `database_stroke.csv` (the registry export with patient names and telephone numbers, lower-precision values) anywhere in the project; it is not an input and `scripts/privacy_check.py` / the archive allowlist exclude `data/raw` entirely. Every run records the workbook and dictionary SHA-256 in `outputs/manifests/run_manifest.json` and the dictionary file actually used in `outputs/audit/dictionary_audit.json`.

## Reviewer tickets → code → outputs
`docs/tickets.json` holds the 60 tickets derived from the decision letter (IDs as in the Phase 1 audit). `docs/requirements_traceability_matrix.md` maps them to 15 requirements and to modules/outputs. `scripts/ticket_self_check.py` evaluates one or more assertions per ticket (manuscript text, outputs, code) after every run and fails a real-data run on any regression; `docs/ticket_closure.md` is its report and `docs/self_improvement_log.md` records each fix iteration.

## What this project is not
It does not reproduce the June 2026 submitted model results: their final training code was not available, so the revision reports a new analysis reconciled item by item with the submitted numbers (manuscript Appendix B). It contains no patient data; the CSV export of the registry (with names and telephone numbers) must never be placed inside it.
